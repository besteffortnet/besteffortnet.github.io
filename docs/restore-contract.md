# 一覧の版履歴・復元検査

一覧の履歴に掲載された版の参照先や復元手順が壊れると、問題が起きてから過去版の差分を準備できない。この検査は、変更のpushとプルリクエストで、履歴に表示されるコマンドとGit上の復元対象を自動照合する。

## 対象と結果

- 履歴の一意性、明示タイムゾーン、日時の降順を確認する。固定点が未発行の候補は復元コマンドを実行しない。
- 実際の履歴表示用JavaScriptを実行して取得した各コマンドを、許可した書式と照合する。コマンド文字列をシェルに渡さず、安全な引数配列を作る。
- 検証用の一時cloneで各コマンドを実行し、一覧HTMLと並べ替え・観測時刻のスクリプトを対象commitのGit blobと比較する。対象版に存在しなかったファイルは不在を確認する。履歴データは現在のままで、元の作業ツリーの変更状態が変わっていないことも確認する。
- 2026年11月4日の公開履歴57版では、ChromeとWebKitで表示された57コマンドを別の隔離cloneで実行し、対象ファイルの一致と最新履歴の保持を確認した。公開サイトへの切替は実行していない。

タグが欠けた場合、同じ版・参照が重複する場合、日時が降順でない場合、浅いclone、不正なコマンドをそれぞれ失敗として検出する試験も含む。GitHub Actionsでは全履歴を取得した一時環境で実行し、リポジトリ書込み権限を与えない。

## ローカルでの実行

Git、Python 3、Node.jsを使い、全履歴とタグが揃ったこのリポジトリのcloneで実行する。

```sh
node --test tests/restore-command-grammar.test.cjs tests/audit-displayed-restores.test.cjs
node tests/audit-displayed-restores.cjs
```

検査は一時ディレクトリのcloneを使用し、終了時にそのディレクトリを削除する。ユーザーの作業ツリーや公開サイトは変更しない。履歴が浅い場合は検査を保留し、完全な履歴を持つcloneが必要と表示する。

## 優先度と範囲

優先度は86点（利用価値32/35、共通性22/25、実現性16/20、検証・復旧16/20）。履歴の誤りを公開前に検出できることを重視した推定であり、障害率や時間短縮の実測値ではない。現在のアダプターはWebUIアプリ一覧専用で、他のアプリの復元コマンド、稼働中データ、依存パッケージ、復元後の実サービス起動は対象に含まない。全アプリ共通の復元検査は別途必要。
