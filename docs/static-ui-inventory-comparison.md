# 静的UI点検の前回比較

## 計画と優先度

前回と今回の静的UI点検結果を読み、版表記と、履歴・テーマ・一覧導線の手掛かりの変化をアプリ別に示す。新たなHTTP要求やアプリ操作はしない。既存の版観測履歴は収集済みの版情報を扱い、本機能は一覧から各トップHTMLを一括点検した結果の静的UI上の変化候補を扱う。

事前評価は87点（利用価値31/35、共通性23/25、実現性17/20、検証・復旧16/20）。新しい点検結果のうち調査すべき差を見つけやすくすることを評価した。作業時間や障害率の実測ではない。稼働試験が成功するまで完了数に加えない。

## 判定境界

- 両回のID、対象URLのSHA-256、記載された時刻の前後関係を照合し、両方でHTMLを取得できた場合だけ静的な手掛かりや版表記を比較する。対象のパス・クエリの原文は保存しない。ハッシュは秘密化の保証ではない。照合は入力に記載された値の整合検査であり、記録の真正性や端末時刻の正確さの証明ではない。
- 古い点検結果に対象URLのハッシュがない場合、対象が変わった場合、時刻が前後しない場合、取得が失敗した場合は比較不可にする。取得できないことを機能の消失とは扱わない。
- 点検範囲を絞った結果も比較できるよう、一方にだけあるIDは「その結果に含まれない」と報告する。アプリの新規登録・削除と断定しない。
- 「前回は観測・今回は未観測」も、静的HTMLの差による調査候補であり、動的UIの欠落や故障の証明ではない。HTTP区分の変化も原因を断定しない。
- 両入力はサイズ、JSON形式、IDの重複、列挙値、時刻、ハッシュ、静的結果の組合せを検証する。壊れた入力は内容を出力せず拒否する。

## 使い方

`static_ui_inventory.py` の標準出力を、前回と今回の2ファイルに保存してから比較する。保存先には所有者限定など適切なアクセス制限を設定する。次の例は既存の公開CAを使い、対象を2アプリに絞る。

```sh
umask 077
python3 tools/static_ui_inventory.py --ca-file "$HOME/anti/.local/share/hubterm/hubterm-ca.pem" --id equalification --id video-player-2d > previous.json
python3 tools/static_ui_inventory.py --ca-file "$HOME/anti/.local/share/hubterm/hubterm-ca.pem" --id equalification --id video-player-2d > current.json
python3 tools/compare_static_ui_inventory.py previous.json current.json
```

出力の `compared` は両回の静的HTMLを比較できたこと、`not_both_html` は少なくとも一方でHTMLを取得できなかったことを示す。`identity_unknown`、`target_changed`、`non_increasing_time` は比較条件を満たさない。対象が一方の結果だけにある場合の `only_in_previous_report` / `only_in_current_report` は、対象の登録・削除を意味しない。HTTP区分と応答番号の変化は別欄に出す。版表記の変化は、順序の変化も含む。
